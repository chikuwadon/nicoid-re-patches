# v1.9.1-dev.3 resource identity repair

Root cause: the ad-hoc dev.2 resource packaging loop copied only resources.arsc and res/*, dropping AndroidManifest.xml. The raw resource patch consequently left the original nicoid manifest in place instead of restoring the established com.sauzask.nicoid.hls identity and application theme. This explains the separate installation, fresh default preferences/startup screen and mismatched theme reported on-device.

Repair: restore the exact compiled AndroidManifest.xml bytes from git tag v1.9.0. The dev.1 manifest is semantically identical to that official manifest. Retain every dev.2 resource entry byte-for-byte and retain the native method delta byte-for-byte. Only bundle/helper version strings change to 1.9.1-dev.3; DEX signature/checksum are recalculated and validated. No signing keys or patch executor behavior are changed.

Validation:

- New VerifyResourceIdentity191.py rejects the defective dev.2 MPP for its missing manifest.
- Repaired MPP passes full manifest identity/component/theme semantic equality against v1.9.0.
- All 2,806 existing resource IDs/names remain unchanged; 14 resources have been appended since v1.9.0.
- Android manifest name validation and compiled settings validation pass on the actual repaired resource ZIP.
- ZIP integrity, entry inventory, unchanged dev.2 resource bytes, exact official manifest bytes, unchanged native DEX and helper DEX differences limited to the equal-length version string are checked.
- Canonical MakePayload now requires identity-bearing APK resources and always includes the compiled manifest even when its bytes match the original input.
