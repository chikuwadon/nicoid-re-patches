# v1.9.1-dev.5 legacy bitmap compatibility repair

Reported regression: the native video-information tag list disappeared after dev.4.

Cause analysis: the native tag builder loads/scales dicon and dicoff before creating its tag Buttons, within a shared exception-handling block. Dev.4 changed these from PNG bitmap resources to vector XML. A new native bitmap-decoder regression test confirms that the actual compiled dev.4 XML assets are not decodable as bitmaps. Compatible PNG versions restore the legacy image-loading contract without altering the video-information fetching, tag-item creation or tap/hold handlers.

Scope of repair: all 28 refreshed icon families (37 density variants) now keep the original PNG paths, pixel bounds and density qualifiers. Modern flat paths are rasterized to those fixed bounds; no shadows are baked into the images. Toolbar glyphs retain their prior raster foreground palette. The new visibility test also found the small-comment-size glyph too faint at its native 32x18 bounds; its dot weight was corrected while preserving the outer dimensions.

Broader disappearance audit:

- Every one of the 800 original PNG entries in dev.3 retains its bitmap format, density path and pixel dimensions in dev.5, including images outside the refreshed set.
- All 37 refreshed variants pass real Android bitmap decoding, original-width/height comparison and visible-pixel assertions.
- All 2,824 dev.4 resource ID/name mappings, the complete manifest, native method delta and patch executor entries are preserved.
- Helper bytecode is identical to dev.4 except for the equal-length version string and recalculated DEX checksums. Flat tag styling, gaps and prior touch/selection behavior therefore retain their existing implementation.
- 23 Robolectric UI/hold/image-decoding regression tests pass. The intentionally broken dev.4 dictionary vectors reproduce the bitmap-decoder rejection.
- Manifest/settings checks and archive/version integrity checks pass.

Actual on-device tag restoration and a complete screen-by-screen device audit remain unverified. No additional disappearing UI was detected by these automated checks; this does not claim a complete device test. No formal release or remote publication was performed.
