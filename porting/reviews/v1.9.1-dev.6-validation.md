# v1.9.1-dev.6 video list presentation

Based on the dev.5 bundle and its bitmap-compatible assets. Changes are limited to shared video-row presentation and additive metadata retention; no replacement application or resource redesign is introduced.

## Screen behavior

- Ranking/search: posted date precedes title, uploader and the shared statistics row. The native rank value and row-action target remain; metadata reserves their width so long titles cannot paint beneath them. Existing title wrapping/line limits are retained.
- Cache list: posted date, title, uploader and statistics use the common order. Capacity/completion and live download progress occupy a separate auxiliary TextView rather than overwriting the statistics. Unknown statistics are omitted rather than synthesized as zero.
- Local watch history: watched date and reliable watch count lead; posted date follows statistics. Available full video counts are saved separately from the history watch count for subsequent records. Existing stored records remain compatible and use their existing statistics.
- Account watch history: watched date leads; posted date follows statistics. The account endpoint's unreliable watch count is not fabricated.
- Mylist/watch later: native added date leads; the already captured nested video's registeredAt supplies the distinct posted date below statistics. API count metadata supplies available likes as well as the other statistics. Existing multiline mylist notes remain below the auxiliary date.
- Device playlists: persisted playlist-entry date leads. A known video posted date is retained as additive metadata when adding a video; old entries with no known posted date do not invent one. Native adapters, queue controls, selection and transactional storage remain in place.

`VideoRows191` reuses native row IDs/views and the existing theme palette and `VideoCounts` renderer. Dates use Asia/Tokyo, preserving the application's prior timezone, and `yyyy/MM/dd HH:mm` with semantic labels. Title is 15sp, metadata/statistics 12sp; thumbnail keeps 124dp width with 16:9 height and duration in its original corner. Unknown uploader/date/statistics views collapse. Decorative elevation is not added; root background, separators, AppBar and media pixels are untouched.
